Introduction

Blueprint Unchained collects three engine capabilities whose useful surface normally stops at the C++ boundary: quaternion rotation math, engine-managed subsystems and Instanced Struct data. The package contains the complete Blueprint Quaternion, Blueprint Subsystems and Blueprint Instanced Struct toolsets in one plugin.

Use any toolset independently or combine them. A subsystem can own an event queue made from Instanced Struct payloads; those payloads can carry quaternion rotations; quaternion nodes can run inside an Animation Blueprint's thread-safe update. No common framework or base actor ties the three together.

Getting started

Enable Blueprint Unchained in Edit > Plugins and restart the editor when requested. That is the complete installation.

The package contains the same modules as the three standalone products. Do not install a standalone copy of Blueprint Quaternion, Blueprint Subsystems or Blueprint Instanced Struct beside Blueprint Unchained in the same project: duplicate module and reflected class names prevent the project from loading.

Choose the toolset that matches the task below. Each linked manual contains its full setup, reference, recipes and troubleshooting guide.

Blueprint Quaternion

Use Blueprint Quaternion when a rotation should stay a quaternion from input to output. Its 85 pure nodes cover construction, axes, conversion, composition, interpolation, swing and twist, queries, random rotations and raw component math.

Typical uses include shortest-arc aiming, interpolation without unwanted flipping, joint limits, surface alignment, smooth rotation paths and processing noisy tracking input. Every angle pin uses degrees and rotation operations normalize their inputs. The library is BlueprintThreadSafe.

The editor module also replaces the default quaternion property row with Euler, axis-angle and raw component views. The override can be disabled per user.

Read the Blueprint Quaternion manual.

Blueprint Subsystems

Use Blueprint Subsystems for services and state that should belong to an engine-managed lifetime instead of an actor. Create Engine, Editor, Game Instance, World, Tickable World and Local Player subsystems as Blueprint assets and implement their lifecycle as events.

The plugin discovers these classes, registers them with the engine and keeps otherwise-unreferenced assets in packaged builds. Project settings control search paths and explicit classes, while Blueprint nodes allow dynamic registration and rescanning.

Read the Blueprint Subsystems manual.

Blueprint Instanced Struct

Use Blueprint Instanced Struct when one variable or array must carry values of different struct types. The toolset operates on Unreal Engine's own FInstancedStruct; it does not add a replacement container.

Typed wildcard Get and Set nodes include a struct picker. Other nodes inspect the held type, create a default from a runtime type, compare and print values, export and parse text, and search or filter arrays by type. Native and Blueprint-authored structs are supported.

Read the Blueprint Instanced Struct manual.

Using the toolsets together

A global event service

Create a Game Instance subsystem to own an array of Instanced Struct values. Each system adds its own payload struct, and the service dispatches values according to their held type. The service survives level travel without a manager actor.

Per-world rotation commands

Create a World subsystem that receives Instanced Struct command payloads. One payload can hold a target quaternion, another an axis and angle, and a third interpolation settings. Quaternion nodes apply each command without converting the rotation through Rotator.

Per-player orientation state

Keep each local player's orientation preferences or calibrated tracking state in a Local Player subsystem. Use quaternion smoothing for incoming device rotations and Instanced Struct values when different devices provide different calibration records.

Packaging and platforms

The bundled plugin declares Windows, macOS and Linux as development platforms. Runtime modules also target Win64, macOS, Linux and Android. Editor and UncookedOnly modules stay out of cooked games.

Blueprint Subsystems adds discovered subsystem assets to the cook. The other two toolsets contain code and no assets that need manual cook rules. The package includes no example project or Blueprint assets.

Troubleshooting

Unreal reports a duplicate module or class

Remove the standalone copies of the included plugins. Keep either Blueprint Unchained or the standalone products, never both sets in one project.

I only need one of the three toolsets

Using one part does not require using the others. If installation size or separate purchasing is important, use its standalone product. Functionality inside the bundle is not reduced.

A problem belongs to one toolset

Open that toolset's linked manual and follow its Troubleshooting section. Include the toolset name, engine version and plugin version when reporting the issue.
